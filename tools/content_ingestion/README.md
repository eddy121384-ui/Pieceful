# Pieceful Content Ingestion v0

Issue #9 production-tool checkpoint.

This tool turns external museum records into **authoring candidates** for Pieceful. It is deliberately separate from the shipped runtime catalog: ingestion may contain unresolved taxonomy fields, while `content/catalog_v1.json` remains publication-ready and CI-validated.

## v0 scope

The first working provider is **The Metropolitan Museum of Art** because its Collection API needs no API key and exposes an explicit `isPublicDomain` flag plus Open Access image URLs.

The importer uses the Met's current paginated search endpoint (`/public/collection/v1.1/search`) rather than the deprecated v1 search endpoint.

A Met item is accepted only when:

- `isPublicDomain == true`
- a primary image URL exists
- the image download succeeds (unless `--metadata-only` is used)

The importer never guesses rights from age, artist, title, or visual content.

National Palace Museum Taipei and Rijksmuseum are registered as planned providers in `content/source_providers_v1.json`, but are intentionally not implemented in v0 yet.

## Where downloaded images go

By default everything downloaded or generated by the ingestion tool goes under:

```text
.pieceful-content/
  processed/
    met/
      met_<object-id>.jpg
  manifests/
    met_sample_<timestamp>.json
```

`.pieceful-content/` is gitignored. High-volume image binaries must not be committed to the application repository or its Git history.

The committed repository keeps only small, durable contracts and tooling: taxonomy, provider rules, plans, tests and code. Production object storage/CDN is a later decision.

## Run the 40-image taxonomy sample

From the repository root:

```bash
python tools/content_ingestion/ingest.py
```

The default plan is `sample_plan_v0.json`: eight deliberately different search themes × five accepted public-domain images = a target of 40 candidates.

To inspect metadata and rights without downloading image binaries:

```bash
python tools/content_ingestion/ingest.py --metadata-only
```

A generated manifest preserves source identity, creator/title metadata, source URL, rights evidence, remote image URLs and local staging path.

## Important: these are not yet published puzzles

Every ingested candidate starts with:

```text
taxonomy_draft.status = unresolved
facet_status.* = unresolved
```

That is intentional. The next authoring stages will add vision-assisted semantic tags and objective puzzleability analysis. Only after those fields pass the taxonomy validator may an item be promoted into the shipped Pieceful catalog.

The pipeline is therefore:

```text
museum source
  -> rights gate
  -> local image candidate + source manifest
  -> auto tagging / puzzleability analysis (later)
  -> review exceptions
  -> taxonomy validation
  -> published runtime catalog
```

## Why the Met `primaryImageSmall` is used in v0

v0 downloads the provider's smaller primary image as a **game candidate** so we can cheaply stress-test taxonomy and workflow without filling the repo or local disk with original-resolution masters.

This is not yet Pieceful's final image-normalization pipeline. A later step will define consistent production dimensions, format/compression, thumbnails, object storage and CDN delivery.

## CI

`tests/content_ingestion_smoke.py` is network-free. It verifies that rights gating rejects restricted/malformed records, accepted records preserve the expected source/rights fields, all semantic facets begin unresolved, and the committed sample plan targets 40 images.
